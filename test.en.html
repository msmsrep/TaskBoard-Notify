TaskBoard-Notify Test Site

So that you can try fetching, parsing and toast notifications in the TaskBoard-Notify app even without a real server, this site serves fixed data that mimics real server responses on GitHub Pages. Just edit sources.json in the app to point it here.

This page uses the English data (*.en.*). The Japanese data is listed on the Japanese page.

Connecting the app

The easiest way is Settings → "Add test sources" in the app. Two sources that read this site's data are added right away (no download, no authentication). Your current sources are kept, so remove the test ones with each source's "Delete" when you are done.

Note: for now, the sources added by the app read the Japanese data (schedule/day.html, api/tasks.json), even when the app is shown in English. To read the English data, import the file below.

To import from a file:

  1. In the app, open Settings → "Open definition file" to open sources.json
    (Location: %LOCALAPPDATA%\TaskBoard-Notify\sources.json; LocalState for the MSIX version)
  2. Keep a copy of the original contents, then replace them with the definition below and save
  3. Click "Reload" in Settings (no need to restart the app)
  4. To go back, restore the copy you kept, or delete the file and restart (the app starts from a template with 0 sources)

Definition to paste

sources/sources.pages.en.json (same parsing as the defaults, English data) / sources/sources.custom.json (custom format) Copied

Limitations of GitHub Pages

  • GET only. Because files are served statically, POST cannot be used (specifying POST results in a fetch failure)
  • No login. Remove "Login" from the definition and use "Credential": "None"
  • Filter conditions cannot be sent. A request body such as the task site's View is ignored even if sent
  • Headers are not checked. An Authorization header passes through unchecked (useful for checking the "not registered" message)
  • ?date={Today:yyyy-MM-dd} in the URL is ignored, but it lets you check that placeholders are replaced

To check login, POST, cookies or API key contents, use the mock server in the main repository (dotnet run --project Tests/TaskBoardNotify.TestConsole -- server).

Data updates

The HTML pages hold only times; the app fills in the date with {Today}, so they are always "today's schedule".
GitHub Actions regenerates the dates in the JSON every day (tools/generate.mjs).

All data here is made-up data for testing. It contains no real schedules, tasks or servers.
