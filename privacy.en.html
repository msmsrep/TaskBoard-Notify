Privacy Policy

TaskBoard-Notify (developed and operated by msmsrep) / Last updated: August 12, 2026

This is an English translation of the Japanese privacy policy.

TaskBoard-Notify (the "App") is a schedule and task notification app for Windows. It periodically fetches lists of schedule items and tasks from sources specified by the user, and notifies you with a toast notification before the start time.

The App has no servers operated by the developer whatsoever. No user information is sent to the developer; the App communicates only with the sources the user has configured.

1. Information collected by the developer

None. The App does none of the following.

  • User registration or account creation (it never asks you to enter your name, email address, etc.)
  • Usage analytics, access analytics, or collection of advertising identifiers
  • Automatic sending of crash reports or logs
  • Sending the contents of fetched schedule items and tasks, credentials, or settings to the developer

2. Information stored on the device

The App stores the following information needed for its operation only on the user's device. None of it is sent externally.

What is storedContentsStorage format
sources.json Source definitions (source URLs, fetch intervals, parsing methods, etc.) Plain-text JSON
sources.previous.json The contents just before the definition file was replaced by an import (a backup for restoring) Plain-text JSON
credentials.json User names, passwords and API keys used to authenticate with sources (only if the user registered them in the Settings screen) Passwords and API keys are encrypted with Windows DPAPI (CurrentUser). Only the same Windows user can decrypt them; they cannot be decrypted even if copied to another user or another PC

The storage locations are as follows.

  • Store version / MSIX version: %LOCALAPPDATA%\Packages\{package name}\LocalState
  • exe version (distributed without an installer): %LOCALAPPDATA%\TaskBoard-Notify

You can check the actual storage location from the App's Settings screen.

The contents of schedule items and tasks fetched from sources (title, time, and link URL) are kept only in memory while the App is running, to determine whether they have already been notified. They are not written to files and are lost when the App exits.

3. Communication

Because the App's main function is fetching data from external servers, it communicates over the network. However, it communicates only with the sources the user has written in the definition file (sources.json). No sources are built into the App in advance, and since there are 0 sources in the initial state, no communication occurs.

What is sent

  • HTTP requests to the URLs written in the definition file (executed automatically at each configured fetch interval)
  • If a source requires login: the registered user name and password are sent to the login URL written in the definition file
  • If a source requires an API key: the registered API key is sent in the format written in the definition file (a request header or the request body)

All of these destinations, contents and timings are specified by the user in the definition file. The developer can neither receive nor view the contents of these communications.

Security of communication

Encryption of communication follows the scheme of the URL specified by the user. If you specify https://, communication is encrypted; if you specify http://, it is not encrypted. We recommend using https:// for sources that handle credentials.

About the test site

If you use "Add test sources" in the Settings screen, this site (https://msmsrep.github.io/TaskBoard-Notify) is added as a source. It serves only fixed data for testing, and no authentication is required. This site is hosted on GitHub Pages (GitHub, Inc.), and technical records associated with access are handled according to that company's policies. The developer has not set up any mechanism to identify visitors.

4. Disclosure to third parties

The App never sells, shares, or provides user data to third parties. Including when responding to disclosure requests based on laws and regulations, the developer does not hold any user data and therefore has no data to provide.

5. How to delete data

Store version / MSIX version

When you uninstall the App, the entire LocalState folder is deleted. The stored data described above is deleted along with it.

exe version

Even if you delete the App's files, the %LOCALAPPDATA%\TaskBoard-Notify folder remains. To delete everything, delete this folder manually.

Deleting only credentials

You can delete registered credentials individually for each source in the Settings screen. You can delete just the passwords and API keys while continuing to use the App.
